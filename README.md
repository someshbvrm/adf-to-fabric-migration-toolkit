# ADF → Microsoft Fabric Migration Toolkit

[![CI](https://github.com/someshbvrm/adf-to-fabric-migration-toolkit/actions/workflows/ci.yml/badge.svg)](https://github.com/someshbvrm/adf-to-fabric-migration-toolkit/actions/workflows/ci.yml)
![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![License](https://img.shields.io/badge/license-MIT-green)

**Live assessment report:** https://someshbvrm.github.io/adf-to-fabric-migration-toolkit/
(regenerated by CI on every push to `main`)

`adf2fabric` is a command-line tool that reads an **Azure Data Factory** definition and tells you
what it takes to move it to **Microsoft Fabric Data Factory**:

- **Assess** every pipeline, activity (including activities nested in ForEach / If / Switch / Until),
  linked service, trigger and integration runtime as *supported*, *rework* or *blocker*.
- **Plan migration waves** from the Execute Pipeline call graph, so a parent pipeline is never
  scheduled before the child pipelines it calls. Circular calls and missing references are flagged.
- **Estimate effort** per object and per pipeline.
- **Generate draft Fabric pipeline JSON**: datasets are inlined as `datasetSettings` with their
  parameters substituted, linked services become connection placeholders, Execute Pipeline becomes
  Invoke Pipeline, and blocker activities are kept but deactivated so the draft still imports.

It has no third-party dependencies and works on an ARM template export or a Git-integrated factory folder.

## Sample result

The repo ships a realistic 7-pipeline factory, `samples/contoso_retail`. It covers a metadata-driven
ERP load (Lookup → ForEach → Copy → stored procedure), paginated REST ingestion, Databricks notebooks, a
mapping data flow, an SSIS package, file archiving and a master orchestration pipeline.

```text
$ adf2fabric run samples/contoso_retail -o out
adf-contoso-retail-prod: 7 pipelines, 22 activities | 90.9% ready | 2 blockers | 3 waves | ~77 h
wrote 7 draft Fabric pipeline(s) to out/fabric_pipelines
```

| Wave | Pipelines |
|---|---|
| 1 | `pl_archive_landing_files`, `pl_customer_dimension`, `pl_legacy_finance_ssis`, `pl_metadata_driven_load`, `pl_rest_api_ingest` |
| 2 | `pl_databricks_transform` (calls `pl_customer_dimension`) |
| 3 | `pl_master_daily` (orchestrates everything) |

The blockers are the mapping data flow (rebuild as Dataflow Gen2 or a notebook), the SSIS package, and
the Azure-SSIS runtime. The self-hosted IR, on-prem SQL Server, Key Vault and tumbling-window trigger
are flagged as rework.

## Quick start

```bash
pip install git+https://github.com/someshbvrm/adf-to-fabric-migration-toolkit
adf2fabric run path/to/ARMTemplateForFactory.json -o out
open out/index.html
```

| Command | What it does |
|---|---|
| `adf2fabric assess SOURCE -o OUT [--format html,md,json] [--fail-on-blockers]` | Writes `index.html`, `assessment.md` and `assessment.json`. With `--fail-on-blockers`, the exit code is 2 when blockers exist, so it can gate a CI pipeline. |
| `adf2fabric convert SOURCE -o OUT [--pipeline NAME] [--connections map.json]` | Writes draft Fabric pipelines to `OUT/fabric_pipelines/`. |
| `adf2fabric run SOURCE -o OUT` | Both of the above. |

`SOURCE` is an ARM template file, a folder containing `ARMTemplateForFactory.json`, or a Git-integrated
factory folder (`pipeline/`, `dataset/`, `linkedService/`, `trigger/`, ...).

### Connection mapping

Draft pipelines contain placeholders such as `{{CONNECTION:ls_adls_lake}}`, `{{PIPELINE:pl_x}}` and
`{{WORKSPACE_ID}}`. Pass a JSON map to fill them with Fabric IDs. See
[`samples/connections.example.json`](samples/connections.example.json).

## How the conversion works

| ADF | Fabric draft |
|---|---|
| Copy `inputs` / `outputs` dataset references | `source.datasetSettings` / `sink.datasetSettings`, with the dataset's `typeProperties` inlined |
| `@dataset().table`, `@{dataset().folder}`, `concat(dataset().a, ...)` | The value the activity passes in, or the dataset default |
| `linkedServiceName` | `externalReferences.connection = {{CONNECTION:<name>}}` |
| Lookup / Get Metadata / Delete `dataset` | `datasetSettings` |
| Execute Pipeline | Invoke Pipeline (`InvokeFabricPipeline`) |
| Mapping data flow, SSIS, other blockers | Kept, set `Inactive`, and annotated `[MIGRATION BLOCKER]` |

The compatibility catalogue lives in [`src/adf2fabric/rules.py`](src/adf2fabric/rules.py) and is
easy to extend.

## Project layout

```text
src/adf2fabric/
  loader.py    # ARM template and Git-folder readers
  rules.py     # compatibility catalogue and effort weights
  waves.py     # Execute Pipeline call graph -> ordered waves
  assess.py    # findings, pipeline summaries, readiness
  convert.py   # draft Fabric pipeline generation
  report.py    # HTML / Markdown / JSON output
  cli.py       # adf2fabric command
samples/contoso_retail/   # 7-pipeline sample factory
tests/                    # pytest suite
```

## Development

```bash
pip install -e ".[dev]"
pytest -v
```

CI runs the tests on Python 3.10–3.12. It then assesses the sample factory and publishes the HTML
report to GitHub Pages.

## Limitations

- Draft output is a starting point. Review it in Fabric before running in production.
- Mapping data flows and SSIS packages are flagged, not converted.
- Effort figures are rough planning estimates from fixed per-object weights in `rules.py`.
